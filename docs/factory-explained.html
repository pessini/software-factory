Software Factory / Issue 9 / 19 September 2026

The work belongs to Factory.
The app is your control screen.

You give Factory a request. It plans the work, makes changes, runs checks, and reviews the result. This change lets the same saved run be controlled from more than one place.

01 / The change

Who owns the run?

BB or the command lineSend a request. Read progress. Answer questions. Stop a run.
→
FactoryOwns the run ID, saved records, model choices, time limits, and worker processes.
→
Protected workersUse the native Codex model connection to plan, edit, and review.

Factory stores records outside the target repository. Work can continue after its control screen closes. Reconnect with the same run ID.

02 / What I changed

Removed the BB dependency

  • Own storage and identity. New runs use Factory records, separate from BB conversations.
  • Own workers. Factory starts and stops protected worker processes. It does not need BB child tasks.
  • Shared controls. BB and the command line use the same start, status, answer, resume, and cancel operations.
  • Safe recovery. Factory checks saved work before it continues. An uncertain request is not sent a second time.
03 / What stays the same

The workflow still has rules

LangGraph already controlled the order of the steps. It still does. Python keeps the records and runs the checks.

  • Planner and Reviewer can read source. Builder can change permitted source files.
  • Git data, credentials, policy, and saved evidence stay protected.
  • One run can write to a workspace at a time.
  • ready_for_review means the checks passed. It does not grant new permission to push, merge, or deploy.
04 / A normal run

Start in BB. Keep the run ID.

  1. Select Software Factory in BB. Choose worker models and effort in the Factory panel; BB’s general model menu does not set these choices.
  2. Send your request. Factory saves a run ID and starts the work.
  3. Use /status for progress and /answer for a saved question.
  4. After reopening BB, use /status or /attach RUN_ID. Use /cancel to stop the actual run.
05 / Old work

Existing records are preserved

Old BB runs keep their original records and recovery path. They are not silently moved into the new storage.

New runs use Factory-owned records. Closing a view and cancelling a run are separate actions. Cancellation is complete only after the workers have stopped.

06 / The next setup

Codex control and Router are separate additions

Codex as another control screen

The local tool connection is implemented using MCP, a tool protocol. Later, we can register it in Codex and test a separate task with read-only access to the target. This does not require changing this active conversation.

Router for external models

Router is optional. It would connect protected workers to other model providers. It is not required for the native Codex model connection, and could serve work started from either app. Installation and route testing remain for later.

Real command-line and BB workflows passed. Planner, Builder, and Reviewer used GPT-5.6-Luna at low effort. The BB test restored a saved question after reconnect, accepted its answer, and finished. A separate cancellation test confirmed worker exit. Repeated controls did not start duplicate work.
