# ADK-Rust framework research

Inspected 2026-10-30 against upstream commit `911dc40f5c2125dd5a53c9f67cff3740df86619d` (main, commit timestamp 2026-10-30). This is a source review; upstream tests and an end-to-end migration were not run. Links below pin that revision so later framework changes do not silently change the evidence.

## Feasibility

ADK-Rust provides the relevant building blocks for a Rust graph application with persistent SQLite state. It is a broader agent framework with its own APIs, not a source-compatible LangGraph replacement. `StateGraph`, nodes, conditional edges, checkpoints, interrupts, and `GraphAgent` are present. `GraphAgent` implements the ADK `Agent` interface and can run through Runner and Server. [Graph public API](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-graph/src/lib.rs), [GraphAgent](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-graph/src/agent.rs).

## SQLite persistence has distinct responsibilities

- `adk_graph::checkpoint::SqliteCheckpointer` stores graph execution state, pending nodes, cleared interrupts, retry attempts, child ledger, checkpoint version, and pending writes in `graph_checkpoints`. `new` creates its schema; `from_pool` supports a shared SQLx pool. Its guarded insert and unique index reject stale checkpoint versions. Enable `adk-graph`'s `sqlite` feature (the meta-crate calls this `graph-sqlite`). [Implementation](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-graph/src/checkpoint.rs#L379), [features](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-graph/Cargo.toml#L59).
- `SqliteSessionService` stores ADK conversational sessions/events/state; it does not replace the graph checkpointer. Construct it, call `migrate`, and inject it. It supports `from_pool`; callers supplying a pool configure foreign keys themselves. Its standard constructor configures a 30-second busy timeout. [Implementation](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-session/src/sqlite.rs#L69).
- `SqliteRunStore` is the durable background queue/run-lease store. `SqliteApprovalStore` stores approval requests and decisions. Both offer `from_pool` and `migrate`. These supplement sessions/checkpoints when queue recovery and a persistent approval inbox are required. [Run store](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-session/src/run_store.rs), [approval store](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-session/src/approval.rs).

Recommendation: use explicit file-backed SQLite configuration, a tuned shared pool where suitable, and a persistent Docker volume. Preserve the application's domain ledger and artifact files too; framework persistence alone does not represent factory delivery evidence or an atomic transaction with external Git/PR effects. Configure WAL/busy timeout deliberately and back up consistently. Upstream SQLite checkpointer conformance tests explicitly use a file database, WAL, and busy timeout. [Conformance harness](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-graph/tests/checkpointer_conformance.rs#L23).

## Human approval and restart behavior

The executor restores checkpoints and dynamic interrupt answers; static interrupt state is also checkpointed. Checkpoint durability defaults to `Sync` (write before the next super-step); all modes write pauses/failures before returning. This protects completed graph steps, not arbitrary external side effects that finish before the current step's checkpoint. Keep domain idempotency/reconciliation. [Durability contract](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-graph/src/checkpoint.rs#L120), [executor](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-graph/src/executor.rs).

`GraphAgent` defaults require special care: a paused thread resumes, but a **finished** thread starts the graph again on the next chat turn, retaining previous state. Direct graph invocation instead returns an already-finished thread's state. A factory API must reject unintended re-execution of completed runs and map approval answers explicitly with the resume mapper. [Turn behavior and pause answers](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-graph/src/agent.rs#L53).

The server exposes an approval inbox when configured. AG-UI approval resumes require authenticated caller context and configured approval service; generic graph interrupts still need application-level validation and authorization appropriate to factory gates. Do not equate an arbitrary incoming text message with permission to merge or publish. [Runtime approval resume](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-server/src/rest/controllers/runtime.rs#L1826), [approval endpoints](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-server/src/approvals.rs).

## Server, SSE, and durable execution

Launcher supports `with_session_service`, `with_approval_service`, and `with_background_runs`. Sessions default to in-memory; durable background state also defaults to an in-memory run store unless replaced. Launcher binds loopback by default, so Docker needs an explicit `0.0.0.0` bind. [Launcher](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-cli/src/launcher.rs).

Ordinary `/api/run_sse`/`/api/run/{app}/{user}/{session}` routes return an SSE wrapper around the Runner event stream. The wrapper polls that stream directly, with no detached durable worker in this request path. Therefore do not assume long factory execution continues after a browser disconnect; validate that behavior and use an independent worker for durable factory runs. [SSE wrapper](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-server/src/rest/controllers/runtime.rs#L1410), [route execution](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-server/src/rest/controllers/runtime.rs#L1630).

The separate `background` feature provides `/api/runs` and `DurableWorker`. With durable stores, workers recover expired leases; agent tool approvals park/wake runs. Configure `SqliteRunStore` explicitly. A custom graph workflow using `WorkflowExecutor` must override `execute_durable`, pass `WorkflowRunContext.thread_id` to graph execution, observe cancellation, and report checkpoints; its default implementation restarts from input. Mapping graph pause outcomes into waiting/wake semantics remains application integration work. [Background documentation](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-server/README.md#background-execution-feature-background), [workflow integration contract](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-server/src/background/mod.rs#L303), [worker recovery](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-server/src/background/worker.rs#L1230).

Server has REST/session APIs, SSE and UI protocol support, auth-context integration, host/origin controls, and optional background/approval endpoints. These do not automatically reproduce this project's run-specific API or product UI. Supply authenticated request context for ownership-sensitive operations; background routes without it intentionally operate in open development mode. [Server capabilities and auth](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-server/README.md), [security settings](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-server/src/config.rs#L9).

## External coding-agent integration options

The current Factory native worker speaks Codex App Server, while BB is an ACP
client interface. Keeping that worker protocol initially avoids an additional
protocol migration; ADK ACP support below is an alternative to evaluate.

`adk-acp` offers client/host integration with external coding-agent processes. `AcpAgentTool` launches a new process/session per tool invocation; `AcpSession` retains one process/conversation over prompts, and `stream_prompt` exposes updates. Permissions deny by default and support custom async policies. Its README includes a `codex-acp` example. This is a useful porting option, but the existing protected worker's container isolation, credentials, permissions, cancellation and file-access policy still need implementation and compatibility tests. [ACP README](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/adk-acp/README.md).

## Version and packaging

The inspected main branch declares workspace version `3.0.0`, Rust edition `2024`, minimum Rust `1.95`, and Apache-2.0. These are source metadata, not verification of a particular crates.io release. Pin a tested upstream tag/revision or released crate set and commit Cargo.lock; a moving main branch is unsuitable as a production compatibility target. Check the chosen revision's actual dependency and feature requirements before writing the Docker build. [Workspace metadata](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/Cargo.toml#L140), [license](https://github.com/zavora-ai/adk-rust/blob/911dc40f5c2125dd5a53c9f67cff3740df86619d/LICENSE).

Acceptance gates for a migration spike: crash/restart while waiting for approval; duplicate and stale approval submissions; process death after an external effect but before checkpoint; simultaneous resume attempts; SSE disconnect/reconnect; checkpoint/schema migration; completed-run replay prevention; permission parity for Codex ACP; and restart with the same Docker volume.
